# Hyper-Browsing

> **사용자의 크롬 브라우저를 그대로 활용하여, 복잡한 웹 탐색과 작업을 사용자 대신 수행해 주는 AI 에이전트 브라우징 스킬**

---

## 1. 이 스킬이 지향하는 핵심 목표

기존의 웹 에이전트 도구들은 보통 사용자와 완전히 격리된 별도의 가상 브라우저나 빈 스크래퍼를 띄웁니다. 그 결과:
- 이미 로그인해 둔 사이트(링크드인, 구글, 네이버 등)에 매번 다시 로그인해야 하고,
- 2단계 인증(2FA)이나 보안 확인이 뜰 때마다 봇 탐지에 걸려 멈춰 서며,
- 사용자의 실제 브라우징 맥락을 전혀 이어받지 못합니다.

**Hyper-Browsing**의 본질은 무언가를 강제로 해킹하거나 뚫는 봇이 아닙니다.  
**"사용자가 평소 웹을 쓰는 환경(프로필 세션, 인증 상태)을 안전하게 이어받아, 사용자의 든든한 비서로서 크롬 브라우저를 직접 조작해 요청을 대신 처리하는 것"**입니다.

---

## 2. 돌아가는 기본 원리

```text
[ 사용자 요청: "내 링크드인 최신 피드 요약해줘", "에어비앤비 예약 현황 확인해줘" ]
                                  │
                                  ▼
┌────────────────────────────────────────────────────────────────────────┐
│  1. Hyper-Browsing 스킬 (작업 지시자)                                     │
│     - 사용자 요청을 분석하여 적절한 사이트 러너(<site>_runner.mjs) 실행 │
│     - 필요한 경우 가상 스크롤, 데이터 정제 도구 가동                     │
└─────────────────────────────────┬──────────────────────────────────────┘
                                  │ (안전한 로컬 CDP 제어 통신)
                                  ▼
┌────────────────────────────────────────────────────────────────────────┐
│  2. 사용자의 크롬 브라우저 데몬 (Real Chrome Context)                    │
│     - 사용자의 실제 로그인 세션(쿠키, 스토리지)을 그대로 유지           │
│     - 불필요한 백그라운드 캐시 누적 차단 (가볍고 쾌적한 상태 유지)       │
│     - CAPTCHA나 2차 인증 등 본인 확인이 필요할 때는 화면을 열어 사용자에게 알림│
└─────────────────────────────────┬──────────────────────────────────────┘
                                  │ (실제 사용자 자격으로 브라우징)
                                  ▼
┌────────────────────────────────────────────────────────────────────────┐
│  3. 웹 서비스 (LinkedIn, Airbnb, Naver, KREAM, Skyscanner 등)          │
│     - 사용자가 직접 크롬 창을 켜서 마우스/키보드로 서핑하는 것과 동일함 │
└────────────────────────────────────────────────────────────────────────┘
```

1. **사용자의 브라우저 세션 존중 (Session Continuity)**:
   - 사용자가 한 번 브라우저에서 로그인해 둔 상태를 안전하게 보존합니다. AI가 사용자 대신 웹을 이용할 때 매번 계정/비밀번호를 묻지 않습니다.
2. **자연스러운 브라우저 조작 (Native Interaction)**:
   - 가짜 브라우저 헤더를 흉내 내는 것이 아니라, 컴퓨터에 설치된 실제 구글 크롬 엔진을 활용하여 사람이 직접 탭을 열고 클릭하고 스크롤하는 방식 그대로 동작합니다.
3. **사용자 존중 및 안전 개입 (Human-in-the-Loop)**:
   - 결제 확인, 중요한 2단계 인증, 사람 확인 화면 등이 나타나면 무리하게 조작하지 않고 브라우저 창을 띄워 사용자에게 정중히 확인을 요청합니다.

## 3. 요청 시 뒷단에서는 어떻게 동작하는가?

### 시나리오 1) "링크드인에서 내 피드 최신 글 3개 요약해줘"
- **사용자 관점**: AI에게 말 한마디만 건네면 끝납니다.
- **뒷단 동작**:
  1. 에이전트가 링크드인 러너(`linkedin_runner.mjs`)를 호출합니다.
  2. 이미 로그인된 사용자의 크롬 세션을 열어 링크드인 피드(`linkedin.com/feed`)로 이동합니다.
  3. 로그인 창이나 인증 요청 없이 본인 피드가 열리면, 최신 포스트 3개의 본문과 작성자 정보를 읽어옵니다.
  4. 읽어온 원문 데이터를 에이전트가 보기 쉽게 요약하여 사용자에게 보고합니다.

### 시나리오 2) "KREAM에서 인기 스니커즈 현재 거래가 확인해줘"
- **사용자 관점**: 복잡한 검색과 필터 클릭을 대신해 줍니다.
- **뒷단 동작**:
  1. 에이전트가 크롬 브라우저를 통해 KREAM 사이트에 접속합니다.
  2. 검색창에 키워드를 입력하고 검색 결과를 렌더링합니다.
  3. 화면의 가상 리스트를 매끄럽게 탐색하며 실시간 즉시 구매가와 최근 거래 내역을 추출하여 정리해 줍니다.

## 4. 함께 제공되는 지원 도구들 (`scripts/tools.mjs`)

- **사용자 확인 요청 (`user-intervene`)**: 본인 인증이나 결제 등 사람의 손길이 필요할 때 브라우저 창을 즉시 표시하고 입력을 기다립니다.
- **부드러운 화면 탐색 (`smart-scroll`)**: 내용이 긴 무한 스크롤 웹페이지에서도 데이터 유실 없이 사용자 대신 끝까지 스크롤하며 내용을 읽어옵니다.
- **실시간 데이터 수신 (`sniff-ws`)**: 차트나 호가 등 화면에서 실시간으로 변하는 데이터를 브라우저 뒤편에서 깔끔하게 받아옵니다.

---

## 5. 브라우저 캐시 및 저장공간 관리

크롬을 오랫동안 쓰다 보면 쌓이는 불필요한 그래픽/셰이더 캐시와 백그라운드 찌꺼기 파일은 사전에 방지되며, 원클릭으로 정리할 수 있습니다. **로그인 세션(쿠키)은 안전하게 보존**됩니다.

```bash
npm run clean
```

---

## 6. 개인정보 및 보안 안내

- **저장소에는 어떠한 로그인 정보, 쿠키, 개인 식별 데이터도 포함되지 않습니다.**
- 모든 인증 정보와 쿠키는 사용자 본인 컴퓨터의 로컬 환경(`.runtime/`)에만 머무르며, Git 추적에서 엄격히 제외되어 있습니다.
