# HB 관찰 단계별 비용 측정

2026-10-14, 로컬 HTML의 버튼 10/100/300개를 각각 3회 수집했다. 실제 HB captureSnapshot을 사용했고, 조작·학습·LLM·다른 브라우징 도구 비교는 수행하지 않았다. raw 데이터와 실행 조건은 [results.json](results.json), 실행 코드는 [run.mjs](run.mjs)이다.

```powershell
node --import tsx benchmarks/hwm-reference-phases-2026-10-14/run.mjs
```

| 버튼 수 | 전체 관찰 ms | 페이지 평가 ms | 결과 전송 ms | 참조 바인딩 ms |
|---|---:|---:|---:|---:|
| 10 | 28.2 | 2.2 | 5.3 | 18.0 |
| 100 | 138.2 | 3.7 | 23.9 | 109.1 |
| 300 | 424.4 | 12.8 | 81.5 | 343.0 |

각 열은 독립 중앙값이므로 합계가 반드시 일치하지 않는다. 페이지 평가는 브라우저 계산과 호출 왕복을 포함한다. 결과 전송은 반환 객체 추출·직렬화·전송을 포함한다. 바인딩은 핸들 접근/등록/일부 해제 호출이며 순수 생성 비용 또는 정확한 CDP 호출 횟수가 아니다. 비동기 해제 완료는 별도 reference 진단으로 확인한다.

이 로컬 조건에서는 바인딩이 큰 비용이다. 다만 복잡한 실사이트의 렌더링/수집 비용이나 지연 바인딩의 성능 이득을 측정한 결과는 아니다. 지연 바인딩의 역조회 테이블·메모리 상한·퇴출·문서 정리·stale_ref 계약을 정한 뒤 동일 조건으로 비교할 후보로 삼는다.

결과에는 registeredReferences, pendingDisposals, disposalSettled/Failed, lastInvalidation도 보존했다. 이 수치는 호스트 참조 등록과 해제 요청 상태이며 브라우저 전체 메모리나 GC 완료를 뜻하지 않는다. 별도 회귀 fixture는 같은 화면의 12회 수집에서 등록 수가 증가하지 않는지, 문서 이동 후 기존 참조 해제가 완료되는지 확인한다.
