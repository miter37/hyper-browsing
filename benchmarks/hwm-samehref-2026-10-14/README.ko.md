# 같은 href 자동 선택 제거 — 최소 비용/정확성 실험

2026-10-14 · feat/hwm-0.2 · 로컬 HTML 두 사례, 방법별 각 3회(총 12회).

결론: 모호함을 반환하는 것은 공짜가 아니다. 동등한 두 링크에서는 추가 호출과 출력 비용이 생겼다. 하지만 href가 같고 클릭 핸들러가 다른 사례에서는 첫 후보 자동 선택이 잘못된 대상을 실행했다. 이는 href 동등성만으로 동작 동등성을 보장할 수 없음을 보여주는 작은 반례이며, 실제 웹에서의 발생 빈도나 전체 성공률을 추정하는 실험은 아니다.

## 방법

- 두 방법 모두 실제 Chrome과 HB executePrimitive의 공통 입력 지연·대상 확인·위험도·조작·결과 관찰 경로를 사용했다. browser-use/다른 브라우징 제품을 실행하지 않았다.
- baseline은 현재 HB에서 nth=0으로 제거 전의 첫 후보 선택을 재현했다. **구버전 전체를 실행한 비교가 아니라 해당 선택 정책의 에뮬레이션**이다. 명령/결과 기록에도 실제 nth 입력을 포함했다.
- 새 방식은 먼저 같은 이름으로 요청해 ambiguous/candidates를 받고, fixture의 요구에 맞는 영역을 within으로 지정해 한 번 더 실행했다. 후보 선택은 고정된 테스트 정답을 사용하며 LLM을 호출하지 않았다.
- equivalent: 두 링크의 목적지와 핸들러 효과가 모두 동일하다. 어느 쪽이든 정답이다.
- different-handlers: href는 같지만 Alpha/Beta의 핸들러가 다른 효과를 낸다. Beta가 요구 대상이다.
- 반복별 방법 순서를 교차하고 각 시행에 새 브라우저 컨텍스트를 썼다. HTML 준비/브라우저 시작은 시간에서 제외했다.
- 시간은 명령 시작부터 마지막 HB 결과까지다. 각 입력의 랜덤 500–1000ms 지연이 포함되므로 3회 중앙값은 거친 관찰이다. LLM 사고·네트워크 RPC·전체 과업 비용은 포함하지 않는다.
- 토큰은 요청+결과 JSON을 gpt-tokenizer의 **o200k_base**로 센 비교용 수치다. 실제 소비 모델의 tokenizer, 대화 포장, 시스템 프롬프트, 추론 토큰과 같다고 주장하지 않는다. [사용한 tokenizer](https://github.com/niieani/gpt-tokenizer).

## 결과(중앙값)

| 사례 | 선택 방식 | 정확성 | HB 호출 | 시간 | 요청+결과 토큰 |
| --- | --- | --- | --- | --- | --- |
| 동등한 링크 | 첫 후보 선택 에뮬레이션 | 3/3 | 1 | 0.994초 | 61 |
| 동등한 링크 | ambiguous → 범위 지정 | 3/3 | 2 | 1.999초 | 197 |
| 다른 핸들러 | 첫 후보 선택 에뮬레이션 | 0/3 | 1 | 1.163초 | 61 |
| 다른 핸들러 | ambiguous → 범위 지정 | 3/3 | 2 | 1.869초 | 197 |

동등 사례에서 추가 비용은 호출 1회, 약 1.005초, payload 토큰 136개였다. 다른 동작 사례에서는 약 0.707초와 같은 토큰 증가를 지불하고 올바른 대상을 골랐다. 출력 토큰만 보면 41→161이었다.

## 개발 판단

same-href 자동 선택은 복원하지 않는다. 다만 ambiguity의 비용을 없는 것으로 취급하지 않는다. 후보의 소속·목적지를 최초 관찰에 함께 제공하고 명시 ref를 바로 사용하게 해 첫 실패 호출을 줄이는 방향을 다음 렌더러/후보 검증에서 측정한다. 이것은 이번 실험에서 아직 검증한 최적화가 아니다.

구매/발송 등 실제 외부 변경을 시험하지 않았다. 결과는 로컬 합성 사례에 한정된다.

## 재현과 원시 기록

[run.mjs](run.mjs), [results.json](results.json)에 명령·결과·개별 시간·토큰·선택 효과를 보존했다.

```powershell
npm install --prefix .runtime/hwm-samehref-benchmark --no-save --package-lock=false --ignore-scripts gpt-tokenizer
node --import tsx benchmarks/hwm-samehref-2026-10-14/run.mjs
```

tokenizer는 개발 비교를 위한 로컬 .runtime 의존성이다. 프로젝트의 제품 dependency에는 추가하지 않았다. 재실행 시 라이브러리 버전과 환경을 기록해야 한다.
