# 실전 테스트 기반 보완 후보

테스트 중 제품은 변경하지 않는다. 여섯 시행 종료 후 재현·원인 확인을 거쳐 공통 계층을 수정한다. 사이트별 하드코딩은 추가하지 않는다. 과업 오답과 앱 결함을 구분한다.

## Wikipedia

1. 저장 거절 시 조회 결과는 observation_expired지만 최초 보관 실패와 실제 TTL 만료는 다르다. retention=unavailable의 구체 이유와 대체 조회 경로가 사용자가 읽는 출력에 충분한지 확인한다.
2. overview 요청 후 retention 불가 시 full 6,000노드(949,751 UTF-8바이트)를 반환했다. 내부 정책인지 확인하고, 저장 불가 때문에 무제한 출력으로 변하는 비용을 검증한다. 접힌 내용의 실제 펼침 가능성을 거짓으로 약속하지 않으면서 출력 예산을 지키는 정책이 필요하다.
3. @links의 수집 참조 수 exact=true와 graph scan.complete=false가 함께 있다. 전체 문서의 목적지 링크 개수와 부분 그래프의 실행 참조 수가 섞이지 않도록 범위 표현을 검토한다. 원시 전체 DOM 수와 등록 실행참조 수를 같은 값으로 취급하지 않는다.
4. 에이전트가 전체 링크 합계 검증 전에 cleanup했다. 앱 오류와 별개인 수행 절차 문제다. 최종 과업 체크리스트와 cleanup 전 누락 점검으로 보완한다.

## eBay 진행 중

1. 실행이 진행 중인데 agent가 session open을 다시 보내 두 세션이 생겼다. 실험 wrapper에 명령 동시 실행 거부 잠금을 추가했다. 제품 RPC 재실행 결함으로 단정하지 않으며 에이전트의 tool session 대기 절차를 기록한다. 최초 두 로그 sequence=1 충돌로 원시 출력 한 파일이 덮여쓰기 되었으나 jsonl에는 두 호출의 시간·인자를 보존했다.
2. Sponsored를 제외한 두 번째와 페이지의 두 번째 상품을 혼동했다. root가 cleanup 전에 정정했다. 앱에서 광고 의미를 분류하지 않고, 카드 경계와 원문 표식/순서를 보존할 수 있는지 확인한다. 이 시행은 감독 정정이 개입된 것으로 보고한다.
3. HWM overview, HWM query, action after 출력의 실제 mode/크기 차이를 측정한다. 동작별 full 기본값은 명시된 계약이므로 결함으로 단정하지 않는다.

## GitHub

1. overview에서 개수 찾기 실패 후 전체 텍스트 fallback 2회. 실제 입력 후 HWM full에는 Open 170이 포함돼 있다. 수집누락이라고 단정하지 않고 overview 선택·query 일치 정보·focus의 접힌 내용 발견 가능성을 점검한다.
2. fill 후 URL/입력/목록 값이 함께 살아 있고, submit 후 URL와 결과 문구가 바뀌는 것은 목표한 계약에 맞았다. navigation에서 incomparable은 오류가 아니라 올바른 동일성 한정이다.
3. 에이전트가 초기 상태와 입력 후 상태를 최종 답에서 혼동했다. 보고를 과업 시점별로 구조화하고 원시 after-fill 근거를 보존한다. root는 새로운 페이지 조회 없이 command-007로 제출 직전 상태를 재확인했다.

## MDN 진행 중

1. expand target=gap12가 observation_node_not_found로 실패했다. 원시 누락 gap과 출력 projection의 실제 expand 핸들을 구분하기 어려운지 점검한다. 잘못된 핸들 허용을 위해 새 DOM을 읽거나 대상을 추측하지 않는다.
2. 검색 창을 여는 button은 HWM focus보다 기존 snapshot --query Search에서 빨리 확인했다. 같은 그래프 안에서 후보 검색/범위를 사용하기 편한지 측정한다.

## 완료 후 원인 확인 및 보완

- **수정 완료:** 보관 거절 fallback에 projection 옵션을 전달하지 않아 full이 되는 것을 재현했다. 요청한 투영을 유지하고 보관되지 않은 숨김 내용은 unavailable로 바꿔 펼침을 약속하지 않는다. retention에 구체 reason을 넣는다.
- **수정 완료:** 거절된 ID 조회와 실제 만료를 구분하는 내용 없는 제한적 거절 기록을 추가했다. TTL과 FIFO 개수 상한, 세션 범위를 유지한다.
- **수정 완료:** 원시 gap에 expand 요청 시 observation_gap_not_expandable로 구분한다. 새 DOM을 읽거나 임의 대상을 대신 고르지 않는다.
- **수정 완료:** list의 120/200자 제목·본문 발췌는 잘림 여부/원문길이/표시길이를 알리지 않았다. Unicode code point 기준 잘림 메타정보를 추가했다. 광고 등의 의미 해석은 넣지 않았다.
- 위 4개 회귀 테스트는 로컬 임의 HTML/HB 경로에서 RED→GREEN. 6개 실사이트는 재시행하지 않았다.
- **남음:** MDN의 긴 앞쪽 메뉴가 기본 2000노드 예산을 소진한다. 전체 그래프 순서를 보존하면서 요청 범위에 필요한 수집을 확장하는 설계가 필요하다. 도메인/태그 조합을 특정 사이트에 맞추지 않는다.
- **남음:** GitHub overview의 접힌 개수 찾기에 eval을 썼다. 저장 그래프 검색·후보 우선 투영을 검증해야 한다. 기존 after-fill HWM에 값이 존재하므로 진짜 수집 누락으로 부르지 않는다.
- **남음:** Booking 필터 후 ready지만 목록 없음. 사이트 이동 URL에 조건을 임의 덧붙이지 않는다. 목록 범위·현재 폼 조건·문서 상태의 충분한 근거와 기다림 기준을 보강하는 공통 과제로 남긴다.
- **실험 절차:** 감독 정정과 잘못된 정리/대기/경로 사용을 결과에 기록한다. 자동 성공률에 섞지 않는다. 인프라 lock와 cleanup 후 명령 거부는 제품 기능 수정과 분리한다.
