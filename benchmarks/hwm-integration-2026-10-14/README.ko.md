# 통합 전후 로컬 수집 비용

기준선 baseline.json은 통합 수정 직전의 작업 트리에서 본문 문맥 수집을 끈 기존 captureSnapshot 경로로 측정했다. 이 파일을 보존하며 현재 코드로 재생성하지 않는다. 최종 integrated-isolated.json은 실전 서브에이전트와 전체 검사를 종료한 상태에서 같은 HTML을 통합 수집했다. 각각 18회 중 워밍업 3회 제외, 15개 표본이다. 로컬 fixture의 HB 관찰 비용이며 외부 사이트 성공률 실험이나 다른 브라우징 엔진 비교가 아니다.

| 항목 수 | 기존 중앙값 / p95 | 통합 중앙값 / p95 | 중앙값 변화 | p95 변화 |
| --- | --- | --- | --- | --- |
| 30 | 38.99 / 45.44ms | 28.77 / 39.15ms | -26.2% | -13.8% |
| 100 | 110.11 / 146.84ms | 76.47 / 95.18ms | -30.5% | -35.2% |
| 300 | 190.11 / 218.99ms | 200.86 / 240.43ms | +5.7% | +9.8% |

수집 중앙값 +15%, p95 +25% 목표는 모두 통과했다. integrated-final.json의 30항목 p95=68.47ms는 다른 실전 브라우저가 실행 중인 측정이므로 보존하되 고립된 비용 판단과 섞지 않는다. integrated.json은 이전 통합 중간 결과다. 시간 측정에는 capture/전송/참조 등록/상태 확인을 포함하고 렌더링은 별도 renderMs로 기록한다.

**출력 비용은 별도 한계다.** 기존 제어 중심 snapshot JSON은 30/100/300항목에 약 4.7/14.5/23.3KB였고, 최종 HWM overview는 같은 fixture에서 약 34.4/111.4/197.0KB다. HWM에는 추가 본문/소속/개요/위치 상태/출처가 있으므로 정보 범위가 다르다. raw box/space는 기본 뷰에서 제외하고 full/inspect에 남겼지만, 이번 구현이 토큰 비용까지 줄였다고 주장할 수 없다. bytes는 토큰 수가 아니다. 실제 작업의 snapshot+eval+추가 조회 전체 비용과 정답을 비교하는 후속 검증이 필요하다.

실행: `node --import tsx benchmarks/hwm-integration-2026-10-14/cost.mjs integrated-new-label`. 기준선은 덮어쓰지 않는다. 단회 짧은 표본의 시간 분포는 환경 노이즈에 민감하며 큰 실사이트의 최악 비용을 보장하지 않는다.
