# 통합 기본 HWM 단회 검사 — 루트 검토

2026-10-14 · GPT-6 Codex. Luna medium 세 명을 한 명씩 순차 수행시켰다. 각 초기 프롬프트에 문법을 직접 설명했고 학습은 껐다. 각 사이트 1개 trial, 비교 엔진은 사용하지 않았다. 제품은 시행 중 동결했으며 세 시행 이후 기본 뷰의 원시 좌표 축약만 로컬 회귀로 보완했다. 정본/full/inspect는 같은 좌표를 유지한다.

시간은 첫 브라우징 CLI 시작부터 마지막 브라우징 CLI 종료까지이며 준비/정리와 에이전트의 보고 작성은 제외한다. 브라우징 CLI에는 홈 open/관찰/조작/상세 조회를 포함하고 help/잘못된 cleanup/close는 제외한다. 순수 사고 시간은 측정하지 않는다. 원시 명령 집계는 [metrics.json](metrics.json)이다. 에이전트 개별 보고의 44초/121초/90.6초는 구간 정의가 다르므로 이 표와 혼용하지 않는다.

Best Buy는 국가 선택 화면에서 United States 클릭 후 같은 화면에 남았다. completed는 클릭 명령 완료일 뿐 검색 성공이 아니었다. 클릭 후 추가 관찰이나 역할·이름 선택을 시도하지 않고 종료했으므로 제품만의 실패로 확정할 수 없다. 잘못된 cleanup 호출은 제품 과업 실패와 별도로 집계했다.

Walmart는 headless→headed 뒤에도 CAPTCHA 신호가 남았다. 잘못된 `pending` 세션 조회와 홈 재오픈이 실제로 있었다. 개별 보고의 “재시도 없이”라는 문장은 정확하지 않으며 재오픈을 포함해 집계했다. 초기 루트 프롬프트가 open 결과 키를 sessionId로 설명한 오류도 영향을 줄 수 있다. 실제 키는 id다. 본 시험 백엔드 전체 cleanup은 완료됐고, cleanup 후 close 재호출은 래퍼가 거부했다. 인증을 우회하지 않았다.

Expedia는 초기 CAPTCHA 프레임 진단 뒤 자동 headed 전환했고 후속 관찰은 정상 홈이었다. Stays 선택만 확인했으며 목적지/날짜 적용/검색/필터/숙소 정보는 미완료다. 에이전트는 정본 n154가 실행 ref가 아니라는 것을 올바르게 구분했지만, 기존 역할·이름 선택자가 여전히 가능하다는 점을 활용하지 못하고 조기 종료했다. 초기 명령 안내에 이 대안의 실제 예제가 부족했다. “actionRef가 없다”를 “조작 불가능”으로 읽는 것은 제품 계약이 아니다. 홈 Stays 선택을 요청한 4개 체크포인트 중 하나로 추가 집계하지 않았다.

세 결과로 실전 성능 개선을 주장하지 않는다. 이전 문법 안내 시행은 Best Buy 2/4, Walmart 4/4, Expedia 1/4였지만 사이트 상태·프롬프트·제품 버전·조기 중단이 달라 동등한 비교가 아니다. eval 0회도 정보 읽기 과업을 완료하기 전에 종료했으므로 효율 개선의 증거가 아니다.

공통 보완 후보: 발급 ref가 없는 관찰 노드에 역할·이름/범위 선택의 사용 가능한 절차를 일관되게 안내; 자동 전환의 당시 진단과 후속 정상 화면을 구분; 실제 session open id를 명령 예제로 제공; 충분한 근거가 있는데도 read-only ID 때문에 과업을 중지하는 에이전트 지침 점검. 특정 도메인 우회 URL이나 사이트 조건을 제품에 추가하지 않는다.
