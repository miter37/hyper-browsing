# 실전 실험의 과정 분석 기록

최종 성공·실패뿐 아니라 각 판단에 무엇을 전달했고 왜 다시 조회했는지 기록한다. 원시 페이지·계정·쓰기 결과는 `.runtime`에 보관하고 공용 문서에는 민감정보를 제거한 공통 발견만 남긴다. 학습 OFF와 관찰용 일시 데이터는 별개다.

## 실행 조건

- 시각, 모델, 브랜치/커밋과 dirty 여부, 프로젝트 스킬·실행 파일의 절대 경로
- 사이트·과업, headed/headless와 전환 이유, 학습 여부
- 실행 횟수와 제한 시간, 원격 쓰기 승인 범위
- 상위 에이전트가 제공한 사전 지식·경로와 도중 개입

## 호출별 기록

| 순서·시간 | 요청·want·scope·at | 실제 응답 종류·바이트 | 이미 준 정보/새 정보 | 판단·다음 행동 | 막힘·복구 |
|---|---|---|---|---|---|

각 전환에서 다음을 확인한다.

1. 메뉴를 열었을 때 반환한 실제 선택지·역할·ref를 썼는가? 다시 물었다면 무엇이 부족했는가?
2. 페이지 이동 후 지도는 큰 구조와 현재 항목을 충분히 보여줬는가? 개요 대신 본문 전수 조회로 갔는가?
3. 필요한 패널·섹션·항목만 조회했는가? 무관한 사이드바나 이전 내용이 섞였는가?
4. 같은 대화상자에서 전체 지도를 다시 받았는가? 전달 기준이 끊겨 이미 준 내용이 반복됐는가?
5. 잘못 해석한 필드는 이름·role·hint·href·상태 중 무엇인가? 출력 결함과 LLM 판단 오류를 구분했는가?
6. 오류 뒤 이미 실행된 쓰기를 반복하거나 불필요한 팝업 닫기·스크롤·광범위 HWM을 했는가?

## 결과와 개선 후보

실제 달성 범위·미확인 범위·차단 사유를 나눈다. 전체 경과시간과 호출 수, LLM에게 전달한 출력 전체 바이트, 추가 조회·중복 정보·상위 개입을 함께 집계한다. 명령 사이 시간은 순수 사고시간으로 부르지 않는다.

개선 후보마다 원시 근거 위치, 재현 여부, 공통 원인 가설, 코드 변경과 스킬 변경, 기대 효과와 부작용을 남긴다. 특정 사이트 이름·경로·메뉴 문구를 조건으로 넣어 해결하지 않는다. 아직 측정하지 않은 개선 효과는 가설로 표시한다.

검증을 승인받지 않은 개발에서는 실행하지 않고 미검증 항목으로 남긴다. 원격 쓰기를 분석·회귀 목적으로 재실행하지 않는다. 발견은 `docs/common_findings.md` 아래에 날짜시간·모델명과 함께 누적한다.
