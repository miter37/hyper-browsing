## 후속 원인 조사와 보완안

2026-10-16 · GPT-6 Codex. 제품 코드 수정 없이 로그/코드를 대조하고 `.runtime/maps-cause-probe.mjs`로 로컬 최소 재현을 했다.

### 확인한 원인과 한계

1. `references.ts`는 메인 프레임 framenavigated를 모두 실제 문서 교체처럼 처리한다. 로컬 pushState에서 버튼 DOM 객체가 그대로인데 이벤트1회, document 세대 증가, 기존ref stale_ref를 재현했다. 실제 지도3건의 stale 모두 동일 원인이라고 입증한 것은 아니다. 페이지 상태 전환과 실제 문서/실행컨텍스트 수명은 별도로 관리해야 한다.
2. 입력 검색어 계획은 입력 전 accessible-name을 다음 Enter의 목표로 다시 사용했다. 실사이트 Search Google Maps 이름 소실, Choose starting point… → Starting point Seoul Station 변화가 로그에 있다. 따라서 target_not_found2건은 단순 로딩 지연이 아니다. 이미 틀어진 문자열을3초 기다려도 해결되지 않는다. 로컬에서는 동일 input DOM의 label만 바꿔도 기존ref가 stale이 됨을 별도로 확인했다. 이것은 guard의 현재 의도이며 무작정 삭제하면 다른 의미로 바뀐 대상도 실행할 위험이 있다.
3. `runTask`의 목표 검색/전이·복구 준비가 `actOn`의 입력 간격보다 앞이다. .5~1초 간격 중 주소/DOM이 바뀌면 실행 전 거부될 수 있다. 이 순서 자체는 코드에서 확인했으나 지도 각건의 변경 순간은 추적하지 않았다.
4. follow는 즉시 읽기다. 장소 선택 뒤에는 이전 결과의 Directions9개를, 경로 열기 뒤에는 이전 검색창을, Options 뒤에는 경로 모드 radio6개를 읽었다. 반환 데이터가 거짓이라서가 아니라 요청한 다음 화면과 관찰 시점이 어긋났다. 후속 결과가 준비됐을 때 좁게 읽는 계약이 필요하며, 매 중간 행동의 과업 성공 검증으로 되돌릴 이유는 없다.
5. CLI시간 합33.446초, 묶음 내부17.020초, 경과157.511초다. 약124초는 CLI 바깥 모델 계획/출력 해석/도구 간 공백 등이다. 인간 사고시간이나 순수 모델 추론시간으로 단정할 수 없다. 앱 실행만 빨라져도 이 비용은 그대로 남을 수 있다.

### 우선순위

- 1: 실제 Document/실행컨텍스트 교체와 동일 문서 URL 이동 분리. 동일문서 이동에서는 살아있는 노드참조를 보존하되 현재 guard/접속 여부/승인/범위는 확인한다. 패널·전달원장·과거관찰은 URL/화면 변화를 별도로 추적해 오래된 화면을 known으로 오인하지 않도록 한다. 실제 reload/교체/데몬 재시작은 계속 옛ref를 거부한다.
- 2: 알려진 동일 입력에 fill→Enter를 연결할 때 입력 전 이름으로 재검색하지 않는 명시적인 동일대상 연결. 같은 DOM 객체라는 사실만으로 의미 안전을 보장하지 않으므로 허용된 변경과 변경되면 중단할 속성을 구분한다. 다음 목표를 모두 역할만으로 느슨하게 검색하거나 guard 전체를 없애지 않는다. SKILL의 같은입력 연속조작 예시와 런타임 지원을 함께 정리한다.
- 3: .5~1초 입력 간격 이후 목표 확보에 가깝게 실행 준비를 배치. 준비 도중 의미/문서가 바뀌면 실행 전 중단한다. 이미 수행한 변경/unknown을 재실행하지 않는다. 공통 입력 간격을 이중 적용하지 않는다.
- 4: 마지막 요청 관찰에 한해 국소 결과 준비 후 읽기. 응답에서 예상한 영역이 아니면 관련 영역 또는 아직 준비 전이라는 사실을 반환한다. 알려진 독립적 다음 조작까지 매번 막지 않고, 전환과 무관한 Zoom/모드라디오를 의미 결과처럼 전달하지 않는다.
- 5: 목록·본문의 기본 내용 투영은 보존 정본과 분리해 보이는 유효 텍스트/컨트롤을 우선한다. 숨은 래퍼·아이콘·중복문구가 예산을 소모하는 문제와 카드/행 소속 보존을 함께 본다. 전체 HWM/원문을 기본 출력으로 되돌리지 않는다.

각 변경은 사이트 이름 없는 로컬 HTML로 pushState/replaceState/hash, 실제 reload, 동적 label, 노드 재사용, 모호한 후보, 지연 팝업, unknown/승인 계약을 검사한다. 기본 출력 크기와 실제 총호출/시간을 같이 비교한다. 이번 조사에서는 개발 구현이나 실사이트 추가 반복은 하지 않았다.

### 모델·실험 설계 보완

CLI query에 쉼표/파이프로 동의어를 합친 것은 모델 사용 실수다. 여러 terms는 JSON 배열로 전달해야 한다. 경로검색 직후 줌처럼 다음 과업과 무관한 동작을 섞어 전환 도중 위험을 키우지 않는다. 먼저 한 목적의 결과를 얻고 다음 독립 활동으로 넘어간다. 기존 장소를 떠났다가 주변검색을 위해 홈페이지로 돌아가는 비용도 있었다. 새로운 메뉴가 필요할 때만 현재 화면의 관련 컨트롤을 관찰하는 전략이 낫다. 이를 새 경고문 누적보다 기존 SKILL 예시의 교정으로 반영하는 편이 적절하다.
