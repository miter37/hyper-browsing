# 집중 관찰 후속 구현

작성: 2026-10-15 · GPT-6 Codex

상태: 구현 반영, 실행 검증 미수행. 사용자가 이번 구현에서 테스트를 하지 말라고 명시했다. 타입 검사·빌드·브라우저 시연·성능 실험도 실행하지 않았다. 이전 검증 결과를 이번 변경의 통과 근거로 사용하지 않는다.

## 목적

요청 중심 관찰 설계를 유지하면서 실전에서 끊어진 부분을 코드와 스킬 양쪽에서 연결한다. 실제 응답에 선택지가 있는데 다시 전체 화면을 읽거나, 필요한 설정 한 곳을 찾으려고 본문 전부를 받는 흐름을 줄인다. 사이트별 메뉴 이름이나 경로에 의존하지 않는다.

## 구현 범위

1. 기존 조작 후 페이지 probe에서 확인한 열린 menu/listbox/dialog의 DOM 정체성을 이용해 로컬 focus를 만든다. 메뉴·목록이 8개 이하이고 항목 데이터가 2KB 이하이면 실제 이름·역할·ref를 직접 반환한다. 더 크거나 부분 관찰이면 표본과 로컬 조회 경로를 반환한다.
2. 불투명 `at`이 지도·패널/대상·실제 전달 receipt·consumer를 묶는다. 응답 수신 후 명시적으로 이어 쓰며 페이지 전역 최신 응답을 추론하지 않는다. TTL 5분, 최대 256개/메타데이터 1MB에 더해 지도·receipt의 보관 한도도 적용한다. 실행 대상 참조와 승인 계약은 그대로 둔다.
3. 지도에 패널 부모와 관찰된 current를 전달한다. 부모 read는 하위 패널을 기본 제외하고 `--include-children`에서만 포함한다. 일부만 잡은 지도는 전체 패널 목록이라고 주장하지 않는다.
4. `read --want outline`은 본문 그래프 없이 제목과 하위 패널을 전달한다. 제목 24개/응답 목표 4KB 범위로 제한하며, 알려진 제목 레벨에 대해서만 섹션 조회 핸들을 발급한다. 제목부터 다음 같거나 높은 레벨 제목 전까지라는 기계적 규칙을 쓴다. 원래 조회 루트를 보존한다.
5. 섹션 경계는 텍스트 노드까지 적용한다. 구조를 유지하기 위한 조상은 전체 내용 조회 대상으로 승격하지 않는다. 불완전한 경계 스캔은 오류로 알린다.
6. 같은 열린 대화상자에서 이어가는 조작은 로컬 내용·컨트롤·상태 차분을 전달한다. 문서 교체 후에는 작은 새 지도를 제공한다. 관찰 실패는 실행 상태를 바꾸거나 실행을 반복하는 근거가 되지 않는다.
7. SKILL의 첫 조회 지침과 CLI 도움말을 at/outline/focus 중심으로 맞춘다. 일반 UI 패턴 지식을 제공하고, 필요할 때 읽는 상세 UI 문서와 실험 과정 분석 양식을 추가한다. HWM은 로컬 모호함을 푸는 상세 경로로 유지한다.

## 정적 검토에서 보완한 경계

- 다음 제목을 감싼 요소가 이전 섹션에 일부 포함돼도 다음 제목 뒤 텍스트가 유출되지 않도록 노드 단위 범위를 사용한다.
- 섹션 안의 조상 target을 선택해 전체 main으로 넓히는 조회를 거부한다.
- 전체 지도에서 연 대화상자도 같은 DOM 정체성을 기준으로 찾아 로컬 차분으로 이어간다.

## 이후 승인 시 확인할 사항

메뉴의 직접 선택, sidebar/main 분리, 제목 경계와 교체, TTL/receipt 제거, 같은 대화상자 연속 조작, 문서 교체, 관찰 오류 뒤 실행 중복 방지를 확인해야 한다. 성능·정확도 향상은 아직 주장하지 않는다. 실험은 최종 결과뿐 아니라 호출별 scope·출력량·중복·판단 근거·상위 개입을 기록한다.
