# 작은 지도와 현재 작업 범위

2026-10-16 · GPT-6 Codex

30개 사이트 조사에서 드러난 공통 문제를 반영했다. 사이트 이름·URL·상품명·달력 문구로 분기하지 않는다. 기존 HB의 선택적 읽기와 실행 참조를 유지한다. HWM 전체 그래프를 기본 응답에 추가하지 않는다.

## 지도에서 알 수 있는 것

- `name`, `nameSource`: `aria-labelledby` 또는 `aria-label`의 명시적 영역 이름이다. 내부 첫 제목을 영역 이름으로 올리지 않는다.
- `headings`: 해당 영역 안에서 확인한 제목 단서 최대 2개다. viewport 응답은 별도 `visibleHeadings`를 사용해 전체 제목 단서를 철회하지 않는다. 다른 패널 아래의 제목과 숨겨진 제목은 제외한다. 중첩된 HTML header는 독립 banner가 아닌 경우 제목 탐색을 막지 않는다.
- `position`: 위·아래·부분 노출 등의 세로 위치다. `horizontal`은 별도로 왼쪽·중앙·오른쪽·전체 폭을 표시한다. 가림이나 클릭 가능성을 보장하지 않는다.
- `basis`: HTML/ARIA landmark, 열린 popover, 펼쳐진 `aria-controls` 대상, 큰 형제 열(`sibling-layout-v1`), 반복 자식 묶음(`repeated-children-v1`), 실제 독립 스크롤 영역(`scroll-container-v1`) 등의 근거다.
- `parent`: 실제 DOM 또는 open-shadow 조상 관계다. 시각적으로 가까운 요소를 가상의 DOM 부모로 합치지 않는다.

랜드마크가 이미 있어도 본문 내부의 큰 열을 살핀다. 구조 탐색은 앞 600개 요소에 한정한다. 2~3개 형제가 각각 최소 폭 max(160px, viewport 13%), 높이 viewport 30%이고, 수평으로 겹치지 않으며 세로로 viewport 20% 이상 겹치는 경우 실제 자식 DOM을 별도 구역으로 보존한다. 카드·행·기사 내부에는 이 열 분할을 적용하지 않는다. 작은 반복 카드는 각자 패널이 되지 않는다. 이는 보수적 경계이며 모든 시각적 구역의 발견을 보장하지 않는다.

랜드마크 탐색 8,000개, 보관 후보 최대 128개, 한 응답 최대 8개 패널, 대표 컨트롤은 패널당 2개·전체 12개다. 추가 구조 후보는 64개에 도달하면 멈춘다. 패널 페이지를 나눌 때 부모를 함께 포함한다. 대표 컨트롤은 현재 viewport 및 스크롤 클리핑 범위에 있는 것만 표본으로 준다. 전체 목록이라는 뜻은 아니다.

## 언제 어떤 정보를 주나

| 상황 | 전달 |
|---|---|
| 최초 진입·명시적 문서 이동 | 작은 전체 지도 |
| 메뉴·팝업·펼쳐진 제어 대상 열림 | 기존 후속 관찰의 국소 focus: 이름/제목 단서/최신 컨트롤 |
| 단순 입력·값 변경 | 기존 effect/current 및 요청한 follow |
| 지도에 있던 실제 DOM 경계가 교체·분리됨 | 행동 결과는 보존하고 새 지도 전달 |
| 스크롤 | 실제 이동량·대상·현재 교차하는 패널의 읽기 진입점. 상단 컨트롤과 본문 전체는 반복하지 않음 |
| 더 자세한 소속이 필요함 | 해당 panel의 outline 또는 좁힌 explain |

명시적인 `aria-controls`/popover 관계가 없는 모든 역할 없는 overlay를 발견한다는 보장은 없다. 현재 실행기의 국소 탐색과 스크린샷 복구도 계속 사용한다. 늦게 나타난 팝업을 위해 비동기 응답이나 상시 폴링을 추가하지 않는다.

## 화면에 보이는 내용 읽기

```text
webctl read --session ID --at AT --panel PANEL --want content,controls --visible
```

`--visible`은 현재 viewport와 조상 스크롤/클리핑 영역에 교차하는 컨트롤 및 텍스트 범위만 읽는다. 겹치는 팝업에 가리지 않았다는 판정은 아니다. 실제 렌더링된 텍스트 rect를 사용하며 화면 밖 조상은 구조 유지용으로만 통과시킨다. 전체 DOM 읽기는 기존대로 동작한다. `offset`은 선택한 범위 안의 DOM 출력 페이지 위치이며 스크롤 위치를 대신하지 않는다. 출력의 `range`는 `dom` 또는 `viewport`다. 범위가 제한된 결과를 페이지 전체의 부재로 해석하면 안 된다.

`scroll`의 `owner`에는 document/element 구분과 실제 전후 offset이 담긴다. 대상 없음은 `scrolled=false`다. HB 출력의 `currentView`에는 현재 범위의 map/at/panel과 위 명령의 진입점이 담긴다. 지도 생성이 실패해도 이미 수행한 스크롤을 재실행하지 않고 observationError만 남긴다.

읽기/지도 모두 기존 전달 ledger를 사용한다. `since` 또는 `at`은 소비자가 받은 응답을 명시하며, 이미 전달한 동일 필드는 재전달하지 않는다. `known`을 0건으로 오해하지 않는다. 새 지도는 새 범위이며 이전 지도의 P 번호를 가져다 쓰지 않는다. 오래된 참조를 새 대상으로 대입하지 않는다.

## 검증 범위

`tests/map-strategy.mjs`는 일반 HTML에서 중첩 header, 숨은 제목, 본문 내부 열, 반복 카드, 독립 스크롤 clipping, 역할 없는 명시적 팝업, CLI 전달, 국소 focus, 동일 문서 DOM 교체를 검사한다. 사이트별 성공률이나 전체 브라우징 속도 향상을 입증하는 실험은 아니다. 수집 시간과 전체 작업 비용은 후속 실제 과업에서 별도로 평가한다.

검증 결과: 표준 `npm test` 종료 코드 0(과업 66, HWM/관찰 146, 학습 35, 실행 68, 브라우저 시나리오 15, discovery 46 통과). 마지막 범위 구분 변경을 포함한 `npm run test:hwm` 재실행은 147/147 통과했고 타입 검사도 통과했다. 로그는 `.runtime/map-strategy-tests-final.log`, `.runtime/map-strategy-hwm-final.log`에 보관했다.
